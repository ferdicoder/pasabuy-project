# AGENTS.md

## Layout
- Two separate npm packages: `backend/` and `frontend/`. Not a workspace — install, run, and build inside each directory (each has its own lockfile).
- Root `package.json` / `tsconfig.base.json` are unused; nothing extends them.
- Backend entry: `backend/src/server.ts` (Express 5, Better Auth, pg/Neon). Frontend entry: `frontend/src/main.tsx` (React 19, Vite, TanStack Query, Tailwind v4).

## Commands
```bash
# backend (cwd = backend/)
npm run dev          # tsx watch src/server.ts → :5000
npm run build        # tsc → dist/ (also the typecheck; no lint/test scripts)
npm start            # node dist/server.js
npm run worker:match # drains match_outbox (see Database schema) — required for matching

# frontend (cwd = frontend/)
npm run dev     # vite → :5173
npm run lint    # eslint .
npm run build   # tsc -b && vite build (typecheck only happens here)
npm start       # serve -s dist -l $PORT
```
- No test suite exists; do not invent test commands.
- Verify frontend changes with: `npm run lint` then `npm run build`.
- Verify backend changes with: `npm run build`.

## Backend conventions
- ESM + NodeNext: relative imports in `.ts` must end in `.js` (e.g. `import { pool } from './config/connectDB.js'`).
- Layering: routers → controllers → services → `sql()` helper in `src/config/query.ts`. Zod validation via `src/utils/validateBody.ts`.
- Better Auth mounted at `/api/auth/*splat` (Express 5 splat syntax) before body parsers; app APIs under `/api/v1/{users,request,trips}`.
- Auth is cookie-based. Protected routes use `requireAuth` (`src/middlewares/requireAuth.ts`); session user lands on `req.user`. Reads like `/getAll` and `/get/:id` are intentionally public.
- CORS origin and Better Auth `trustedOrigins` are `http://localhost:5173` plus optional `FRONTEND_URL` env (`server.ts`, `config/auth.ts`).
- Env (see `backend/.env.example`): `PORT`, `PGHOST`/`PGDATABASE`/`PGUSER`/`PGPASSWORD`/`PGPORT`, `BETTER_AUTH_URL`, `FRONTEND_URL`. Loaded via `import "dotenv/config"`.
- `DATABASE_URL` (Neon direct connection) is also read from `backend/.env` by `scripts/pull-schema.sh` and `src/config/matchWorker.ts` — it is **not** in `.env.example`.
- DB pool always sets `ssl: { rejectUnauthorized: false }` (Neon).
- SQL files are tracked in git (`.gitignore` only excludes `.env`): `backend/schema/**` and `backend/better-auth_migrations/*.sql`.

## Database schema (`backend/schema/`)
- **Pull-only snapshot of the live Neon DB**, generated by `backend/scripts/pull-schema.sh` (needs `psql`/`pg_dump` + `DATABASE_URL`). The live DB is the source of truth: there is **no migrate/apply script** — don't hand-edit `schema/` expecting it to take effect, and re-run the script after DB-side changes so the repo stays in sync.
- Layout: `schema/tables/<table>.sql` (DDL → constraints → indexes → trigger functions → triggers, in that order), `schema/types.sql` (enums), `schema/functions.sql` (non-trigger functions). `pg_attver=…` lines are pg_dump artifacts — ignore them. Hand-maintained ER diagram: `schema/mermaid.md`; table purposes: `schema/TABLES.md`.
- Much of the business logic lives in **DB triggers/functions**, not `backend/src`: requests/trips enqueue to `match_outbox` (+ `pg_notify`), `process_match_outbox()` refreshes `match_candidates`, transactions enforce status-transition whitelists and maintain `trips.reserved_kg` (actor read from `current_setting('app.current_user_id')`, which no app code sets yet).
- Matching requires a **third process**: `npm run worker:match` alongside the two dev servers; failures land in `match_outbox_dead`.
- Table groups: Better Auth (`"user"`, `session`, `account`, `verification` — quoted camelCase columns), core (`requests`, `trips`, `matches`, `messages`), money (`transactions`, `transaction_events`), matching (`match_*`), geography (`regions`, `provinces`, `places`, `place_aliases`, `place_proximity`). Only `"user"`, `requests`, `trips` are referenced from `backend/src` so far; the rest are DB-side only (no routes/services exist for them yet).
- Conventions: uuid-v7 PKs `<entity>_id` (default `public.uuid_generate_v7()`), prefixes `idx_`/`fk_`/`chk_`/`uq_`/`trg_`/`fn_`, heavy use of partial indexes (`WHERE status = …`).
- Undeclared DB prerequisites (pre-enabled on Neon only, nothing in repo creates them): extension **`pg_trgm`** (trigram search) and **`uuid_generate_v7()`** (pg_uuidv7 or PG18). Function `v_match_pairs` is a view that exists only in the live DB — pull-schema never dumps views.
- Place seeds: `backend/db/places_seeds/` (`load_places.sql` run manually via `psql -f`; also builds aliases and `rebuild_place_proximity(60)`).

## Frontend conventions
- All API URLs go through `src/config/api.ts` (`VITE_API_URL` prefix); React Query keys live in `src/config/queryKeys.ts`; shared fetch/mutation hooks (axios `withCredentials: true`) in `src/hooks/useAPI.tsx`.
- Auth: `ProtectedRoutes` checks `GET /api/v1/users/me` and redirects to `/login` on 401. After login, session is read via that endpoint (not a Better Auth client SDK).
- Tailwind v4: configured only by the `@tailwindcss/vite` plugin; styles via `@import "tailwindcss"` in `src/index.css` — no `tailwind.config`.
- Cloudinary uploads happen client-side (`src/utils/uploadImage.ts`) with an unsigned preset; requires `VITE_CLOUDINARY_CLOUD_NAME` and `VITE_CLOUDINARY_UPLOAD_PRESET`.
- Env (see `frontend/.env.example`): `VITE_API_URL`, Cloudinary vars.

## Gotchas
- Backend tsconfig is strict: `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `noUnusedLocals`/`noUnusedParameters`, `verbatimModuleSyntax`.
- Interface files use inconsistent extensions (`.ts` vs `.tsx`); backend has a typo'd filename `user.internface.ts` — don't "fix" renames casually (imports depend on them).
- Vite has no proxy: the frontend calls the backend directly at `VITE_API_URL`; both dev servers must run for full-stack work.
- Full-stack matching also needs `npm run worker:match` (backend) — without it, requests/trips sit in `match_outbox` unprocessed.
